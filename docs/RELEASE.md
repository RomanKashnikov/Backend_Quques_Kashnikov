# Публикация релиза для последнего балла

Локальная Release-сборка — результат компиляции. GitHub Release — опубликованная версия исходников в репозитории, привязанная к тегу, с прикреплёнными файлами. Для выполнения последнего пункта задания нужен именно второй вариант и ссылка на него.

В момент подготовки проекта Git-репозиторий и адрес удалённого репозитория не были предоставлены. Поэтому публикация не считается выполненной автоматически.

## Как опубликовать вручную

1. Создайте репозиторий на GitHub, например `eduqueue-backend`. Выберите доступность в соответствии с требованиями преподавателя. Для публичной сдачи не добавляйте реальные данные пользователей.
2. В Visual Studio откройте решение и используйте **Git → Создать репозиторий Git**. Корень репозитория — папка решения `Backend_Quques_Kashnikov`, содержащая README, postman и scripts. Если репозиторий уже создан, подключите его через предусмотренный VS интерфейс.
3. Проверьте список изменений. В коммит должны входить исходники, решение, документация, postman и scripts. Не должны входить `.vs`, `bin`, `obj`, `App_Data`, ключи и базы. Для этого подготовлен `.gitignore`.
4. Сделайте коммит и отправьте его в репозиторий (**Push**).
5. На GitHub откройте **Releases → Draft a new release**.
6. Создайте тег `v1.0.0` на отправленном коммите, заголовок `ЛР 1 — Web API электронных очередей`.
7. Прикрепите `artifacts/EduQueue-Lab1-v1.0.0.zip`. В описании укажите функции и инструкции запуска. Можно дополнительно прикрепить JSON коллекции отдельно.
8. Нажмите **Publish release** и скопируйте ссылку на опубликованный релиз для преподавателя.

> Web API для управления электронными очередями на учебные мероприятия. Три модели с бизнес-логикой, CRUD, четыре сводных LINQ-отчёта, вход по номеру пропуска и паролю, JWT и роли Admin/User.
