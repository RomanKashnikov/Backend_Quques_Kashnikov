# Электронные очереди в учебном процессе — лабораторная № 1

ASP.NET Core Web API на C# / .NET 8. Проект создан вручную в Visual Studio 2022 и сохранён под исходным именем `Backend_Quques_Kashnikov`.

В этой версии администратор управляет пользователями, очередями и записями участников. Обычный авторизованный пользователь просматривает данные и сводные отчёты. Роли преподавателя, старосты и студента, самостоятельная запись и обмен местами оставлены для диплома.

## 1. Запуск в Visual Studio 2022

1. Откройте `Backend_Quques_Kashnikov.sln`.
2. Дождитесь восстановления NuGet-пакетов. Для первого восстановления нужен интернет.
3. Убедитесь, что стартовый проект — `Backend_Quques_Kashnikov`.
4. В списке рядом с кнопкой запуска выберите профиль **https**.
5. Нажмите **F5**. При первом запуске подтвердите доверие локальному сертификату разработки, если VS предложит это сделать.
6. Откройте `https://localhost:7187/swagger`.

Для сборки: **Сборка → Собрать решение** или **Ctrl+Shift+B**. Для Release выберите `Release` вместо `Debug` на панели VS.

Профиль `http` использует `http://localhost:5046`. Профиль IIS Express имеет другие порты; для инструкции и коллекции проще использовать `https`.

Файл SQLite `App_Data/eduqueue.db` и ключ подписи `App_Data/jwt.key` автоматически создаются при первом запуске в рабочем каталоге приложения. При запуске через VS это каталог проекта. Отдельный сервер базы данных не нужен. Данные сохраняются между запусками. Тесты используют отдельную базу в `artifacts`, не затрагивая рабочую.

## 2. Демонстрационные учётные записи

| Роль | Номер пропуска | Пароль | Возможности |
|---|---|---|---|
| Admin | `100001` | `Admin123!` | Чтение, отчёты, создание, изменение и удаление |
| User | `200001` | `User123!` | Чтение и отчёты |

При первом запуске также создаётся очередь «Защита лабораторной № 1» для группы `ИВТ-21`, открытая для записи. Время мероприятия — через сутки после первого запуска. Учётные записи и очередь создаются только в пустой базе, а не при каждом запуске.

Это учебные демонстрационные пароли, опубликованные намеренно. Данная сборка предназначена для локальной сдачи, а не для размещения в интернете с реальными данными. Пароли в SQLite хранятся как хеши ASP.NET Core PasswordHasher с солью, а не открытым текстом. В ответах API хеши не возвращаются. Регистрации нет: новые аккаунты добавляет Admin.

## 3. Как пользоваться Swagger

1. Раскройте **Auth → POST /api/auth/login**.
2. Нажмите **Try it out** и вставьте:

```json
{
  "passNumber": "100001",
  "password": "Admin123!"
}
```

3. Нажмите **Execute**. Ответ `200` содержит `accessToken`.
4. Скопируйте значение токена без кавычек.
5. Нажмите **Authorize** вверху страницы, вставьте только токен (без слова `Bearer`) и подтвердите.
6. Выполните `GET /api/users` и `GET /api/queues`. Из ответов возьмите реальные ID пользователя и очереди.
7. Чтобы записать пользователя, отправьте `POST /api/entries`:

```json
{
  "queueId": 1,
  "userId": 2,
  "note": "Отчёт подготовлен"
}
```

Здесь ID 1 и 2 относятся к новой демонстрационной базе. Если база уже изменялась, используйте ID из своих ответов. Группа пользователя должна совпадать с группой очереди.

8. Посмотрите `GET /api/reports/queues/1/participants`: в нём будут имена участников и текущие места.
9. Чтобы сменить роль, нажмите **Authorize → Logout**, получите токен второго аккаунта через login и авторизуйтесь им.

JWT действителен один час. После изменения пользователя, пароля или роли все его ранее выданные токены перестают действовать — нужно войти заново. После перезапуска сервера токены продолжают работать до истечения срока, поскольку ключ подписи сохраняется.

## 4. Создание очереди

Пример тела `POST /api/queues`:

```json
{
  "subject": "Программирование",
  "title": "Защита лабораторной № 2",
  "teacher": "Петров Пётр Петрович",
  "groupName": "ИВТ-21",
  "room": "305",
  "note": "Подготовить отчёт",
  "opensAt": "2026-10-20T09:00:00+03:00",
  "closesAt": "2026-10-20T13:00:00+03:00",
  "startsAt": "2026-10-20T14:00:00+03:00",
  "capacity": 20
}
```

Замените примерные даты на нужные вам. До `opensAt` добавить участника нельзя. `+03:00` задаёт московское время. API хранит и возвращает время в UTC; суффикс `Z` означает UTC. Например, 14:00 по Москве соответствует 11:00 UTC.

`closesAt` и `capacity` могут быть `null`: без времени закрытия и без лимита. В этой версии время закрытия, если задано, должно быть позже открытия и не позже проведения. Если время закрытия не задано, запись остаётся открытой до завершения или отмены администратором, даже после начала мероприятия.

`PUT /api/queues/{id}` принимает полную карточку с теми же полями. После открытия менять `opensAt` нельзя. Нельзя уменьшить лимит ниже числа участников или менять группу очереди с участниками.

`PATCH /api/queues/{id}/state` принимает `{"state":"Completed"}` или `{"state":"Cancelled"}`. Повторно открыть такую очередь нельзя. Удаление очереди удаляет также все её записи. Завершение и отмена сохраняют записи для просмотра.

Статусы: `Scheduled` — ещё не открыта; `Open` — запись открыта; `Closed` — истёк срок записи; `Completed` — завершена; `Cancelled` — отменена. Заполненность проверяется отдельно: очередь может иметь статус Open, но не иметь свободных мест.

## 5. Методы API

Все методы, кроме login и страницы Swagger, требуют авторизации. Все POST/PUT/PATCH/DELETE для данных требуют Admin.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/auth/login` | Вход, выдача JWT |
| GET | `/api/auth/me` | Свой профиль |
| GET | `/api/users?group=ИВТ-21` | Пользователи, необязательный фильтр |
| GET/PUT/DELETE | `/api/users/{id}` | Получить / изменить / удалить пользователя |
| POST | `/api/users` | Создать пользователя |
| GET | `/api/queues?group=ИВТ-21&subject=Программирование` | Очереди с необязательными фильтрами |
| GET/PUT/DELETE | `/api/queues/{id}` | Получить / изменить / удалить очередь |
| POST | `/api/queues` | Создать очередь |
| PATCH | `/api/queues/{id}/state` | Завершить или отменить |
| GET | `/api/entries?queueId=1` | Записи, необязательный фильтр |
| GET/PUT/DELETE | `/api/entries/{id}` | Получить / изменить примечание / удалить запись |
| POST | `/api/entries` | Добавить участника в конец очереди |
| GET | `/api/reports/queues/{id}/participants` | Участники очереди с именами и местами |
| GET | `/api/reports/queue-load` | Число участников и свободных мест по очередям |
| GET | `/api/reports/users/{id}/schedule` | Мероприятия, в которые записан пользователь |
| GET | `/api/reports/subjects` | Число очередей и записей по предметам |

Для `POST /api/users` нужны `passNumber`, `firstName`, `lastName`, `groupName` (может быть null), `role` (`Admin` или `User`), `password` (8–128 символов). `PUT` принимает те же поля, но `password: null` сохраняет прежний пароль. Последнего администратора нельзя удалить или лишить роли Admin. Пользователя с записями нельзя удалить или перевести в другую группу до удаления записей.

Для `PUT /api/entries/{id}` передаётся только `{"note":"Новое примечание"}`. Перестановка участников вручную не реализована. После удаления записи места в отчёте пересчитываются с 1, при сохранении относительного порядка остальных.

## 6. Postman и показ на паре

1. Запустите API в VS с профилем https.
2. В Postman выберите **Import** и импортируйте оба JSON-файла из `postman`.
3. Выберите окружение **EduQueue Local HTTPS**. Проверьте `baseUrl = https://localhost:7187`.
4. Если сертификат разработки не доверен Postman, настройте доверие к нему; для локальной демонстрации можно отключить проверку SSL только у локальных запросов.
5. Запустите коллекцию целиком через **Run collection / Collection Runner**, по порядку, одну итерацию.

Коллекция содержит 37 запросов с проверками статусов и нескольких результатов. Она сама получает токены Admin/User, генерирует уникальный номер тестового пропуска и актуальные даты, сохраняет ID созданных объектов, затем удаляет только свои тестовые данные. Запускайте её на учебной базе. После прерванного прогона созданные тестовые записи могут остаться — их можно удалить администратором. На вход установлен лимит 20 попыток в минуту с одного IP; при 429 подождите минуту.

Для демонстрации:

- запрос 01 без токена возвращает **401**;
- запрос 06 с токеном User на добавление возвращает **403**;
- запрос 07 с Admin успешно создаёт пользователя (**201**);
- запросы 24–27 показывают четыре сводных отчёта;
- запрос 20 показывает запрет повторной записи (**409**).

401 означает отсутствие действительной аутентификации. 403 означает, что пользователь распознан, но нужных прав нет. Другие ответы: 200 — успех, 201 — создано, 204 — удалено без тела ответа, 400 — некорректные данные, 404 — объект отсутствует, 409 — конфликт с правилами или связями.

## 7. Проверка и Release

Из папки решения:

```powershell
dotnet restore
dotnet build -c Release --no-restore
pwsh -NoProfile -File scripts/Test-Api.ps1
pwsh -NoProfile -File scripts/Publish-Release.ps1
```

`Test-Api.ps1` требует PowerShell 7, сам запускает Release DLL на порту 5099 с отдельной базой и останавливает сервер после проверки. Проверяет CRUD, роли, отчёты, ограничения, одновременное занятие последнего места и сохранение после перезапуска. При занятом порте: `-Port 5100`. Логи остаются в `artifacts/test-...`.

`Publish-Release.ps1` собирает ZIP `artifacts/EduQueue-Lab1-v1.0.0.zip`: приложение, инструкция, документация, коллекция Postman и `Start-Api.cmd`. Это framework-dependent публикация: на компьютере для запуска нужен **ASP.NET Core Runtime 8**, одного обычного .NET Runtime недостаточно. VS для запуска ZIP не требуется.

Распакуйте ZIP и запустите **Start-Api.cmd**. Откройте `http://localhost:5046/swagger`. В Postman поменяйте `baseUrl` на `http://localhost:5046`. Локальный HTTP в этом варианте используется для простого показа на паре. Закрыть сервер можно Ctrl+C. Рабочая база появится в папке `api/App_Data`.

Инструкция по GitHub Release: `docs/RELEASE.md`. Локальная Release-сборка и GitHub Release — разные пункты задания: наличие ZIP ещё не означает публикацию релиза в репозитории.

## 8. Соответствие заданию и дальнейшее развитие

| Требование | Реализация |
|---|---|
| 2–3 класса с бизнес-логикой | AppUser, StudyQueue, QueueEntry — три основные модели |
| CRUD через контроллеры | UsersController, QueuesController, EntriesController |
| 2–5 запросов объединения | Четыре метода ReportsController |
| LINQ Where и Select | Фильтрация, проекции и отчёты; также Join, GroupJoin, GroupBy, Count, Sum, Max |
| Авторизация отчётов | `[Authorize]` у ReportsController |
| Добавление только Admin | `[Authorize(Roles = "Admin")]` у всех операций изменения данных |
| Release и Postman | Скрипт публикации и коллекция из 37 запросов |
| Релиз в репозитории | Требует отдельной публикации на GitHub; см. docs/RELEASE.md |

Разбор устройства кода и сценарий объяснения на защите находятся в `docs/ARCHITECTURE.md`.

Ограничения учебной версии: одна группа на очередь, преподаватель записан строкой, User является общей ролью читателя, нет самостоятельной записи, обмена местами и учёта прохождения. Порядок определяется сервером, а не часами клиента. Сериализация изменений рассчитана на один процесс API; для нескольких серверов понадобится другая стратегия конкурентного доступа. Схема БД создаётся через EnsureCreated; миграции при будущем развитии нужно будет добавить отдельно. .NET 8 выбран под VS 2022; перед длительной эксплуатацией диплома необходимо обновить платформу.
